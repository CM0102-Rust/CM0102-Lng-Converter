# Translated names (`Data\<language>.lng`)

Read by `database_load_language_names` (0x5339a0, `Database.cpp`), one file per game language: `hol`, `fra`, `ger`, `eng`, `ita`, `por`, `nor`, `esp`, `swe`, `dan`. Tools: `lng_confere.py` (does the game accept it?) and `lng_converter.py` (carries the translations from one database to another).

- **Header:** 8 LE u32: [0] clubs, [1] continents, [2] national team competitions, [3] nations, [4] cities, [5] club competitions, [6] stadiums, [7] staff competitions. If the first u32 is 0xf1fffff1, the values are byte-swapped (0x90c140).
- **Check (0x533e6a..0x533ec5):** [1], [3], [4], [6], [7] and [5]+[2] against the loaded database counts, which come from `index.dat` (the count field, not the file size; 0x528cd4 for stadiums). Clubs are not checked. If one does not match: "v3.9.68 Database..cpp 7784" box (0x53585d), [0xb67a34] is zeroed and it returns without reading any name: everything stays in English.
- **Sections, in file order, without ids (record i belongs to database entity i):** clubs [0] × 0x4f (`club.dat` followed by `nat_club.dat`, national teams at the end), continents [1] × 0xba, national team competitions [2] × 0x53, nations [3] × 0x6d, stadiums [6] × 0x34, cities [4] × 0x34, staff competitions [7] × 0x4f, club competitions [5] × 0x53. Each record mirrors the text fields of the database record from +4 (name, gender, short name, gender, three-letter code, nationality...); the city is the exception: 51 name bytes in the `.lng` against 26 in the database.
- **Empty record = keep the database name:** zeros, with 0xff in the gender bytes (+0x33 and +0x4e in the 0x4f/0x53/0x6d ones; +0x33 in the 0x34 ones; +0x1a, +0x9e, +0xb9 in the continent). Each empty text keeps the database one; the gender is copied anyway and normalised (in `por`, 0xff becomes 1; in the others, ≤ 0 becomes 0). Empty club short name: a national team gets the name cut at 26; other clubs keep the database short name.
- **Clubs:** after the game trims the database (0x5270ed removes unused clubs), [0xae23fc][i] holds the original index of club i, and the load reads record [0xae23fc][i] of the `.lng`; without that table (0x53436e) it reads [0] records in sequence and writes them into the club table without a bounds check. So a `.lng` with too many or too few clubs misaligns the national teams (or reads/writes outside the table), even without the error box.

- **Second reader, `eng.lng` (0x544fc0):** with any language, the game also loads `eng.lng` into a separate object ([0xae2408]), with the same six-count check and a "Database.cpp 19953" box (0x5453a4) if one does not match. Its accessors (e.g. 0x5457dc) return the record text directly, without falling back to the database name; that is why `eng.lng` has no empty records (the 2001 one and the CLZ one), and `lng_converter.py` has `--completar` for it.
- **NickPatcher exe (CLZ 25-26):** both routines and the club trimming are identical to the original, except the 7784 box, which is disabled (5 NOPs on the `call` at 0x5358b7): the game still rejects the `.lng` and keeps English, just silently. The 19953 one is still there.

Measured: the 3.9.68 `fra.lng` is 1,993,486 bytes (the exact sum); the `fra.lng` shipped with CLZ 25-26 belongs to another version of the database (12,008 clubs and 9,128 stadiums, against 12,030 and 9,137 in `index.dat`) and is rejected too.
